# Changelog

This document records every released version of meshio++ — new formats, new operations,
notable enhancements, and breaking changes. Breaking changes are called out explicitly as
**Breaking:**; everything else is additive unless stated otherwise.

**Keep this file current: add an entry in the same change as every version bump.** See the
"Version bumps" section of `AGENTS.md`.

## Unreleased

Performance work from the roadmap's §5; output is unchanged.

- **The CLI loads only the verb it runs** (roadmap 5.12.1, [lazy imports](doc/benchmarks.md#lazy-format-and-operation-imports)): the `choices` of the format options come from the generated `_format_table.py` (`READER_NAMES`, `WRITER_NAMES`, plus installed plugins) instead of `reader_map`, which imported every format subpackage, and `ascii`, `binary`, `compress`, `decompress` and the `iga` verbs import their formats when they run: 488 modules after `build_parser()` instead of 731. `main` no longer imports every verb's module either: a table in `_cli/_main.py` registers each verb's name, aliases and help line, and only the verb on the command line is built, so `meshioplusplus --help` loads 269 modules instead of 480 and `meshioplusplus info --help` 277 (about 40% less wall time for each); `build_parser()` and the `completion` verb still build every verb, and each verb's help is byte-identical.
- **Chunked parsing for the remaining ASCII readers** (roadmap 5.7.2, [benchmarks](doc/benchmarks.md#chunked-number-parsing-and-writers-one-number-at-a-time)): Gmsh 2.2 `$Elements` and Gmsh 4.x element blocks, Medit's vertex and element tables and ASCII STL parse in parallel on a parallel build, each falling back to its serial loop on any input that loop would read otherwise, so the values and errors are unchanged: at tier L on four threads `read_medit` 4.8× faster, `read_gmsh22_ascii` 2×, `read_gmsh_ascii` 1.4×, `read_stl` 1.3×.
- **Ragged blocks carry their CSR arrays** (roadmap 5.6, [benchmarks](doc/benchmarks.md#ragged-rows-that-carry-their-csr)): a jagged polygon or polyhedron block read through the core is a `CsrRows`, a `list` subclass of the same row views that also keeps the flat buffer and its offsets (`data.csr()`), which the core takes back with one copy of each; any change to the list's shape drops them. The round trip is about as fast as before, since the way in was already a span copy; the arrays are there for vectorised Python code.
- **An instruction-count gate on pull requests** (roadmap 5.1.1, [benchmarks](doc/benchmarks.md#instruction-count-gate)): `meshioplusplus_bench_ops --instructions` counts one run of a row under Cachegrind, and the `instructions` CI job fails a tier S row more than 1% above `benchmark/instructions_S.csv` (`tools/bench_instructions.py`). The counts repeat to within 6 parts per million.
- **The MCP read cache copies no array for the read-only tools** (roadmap 5.12.2, [read cache](doc/mcp.md#read-cache)): the cached mesh's arrays are frozen; `stats`, `quality`, `check_quality`, `data_info`, `data_integrate`, `regions`, `diff` and `hausdorff` get private containers over them, and an insert no longer copies the mesh for them either. A tool that changes its mesh still gets a private copy.
- **`edge_index`, `bistride_hierarchy` and the Blender inverse vectorised** (roadmap 5.10.1, 5.10.3, 5.10.5, [benchmarks](doc/benchmarks.md#the-python-layers-graph-kernels)): `edge_index(kind="node")` expands the core's sorted node adjacency (37× faster on 200k ragged polygons, 3.9× on 1.3M tetrahedra); `bistride_hierarchy` drops its per-component scan and dict BFS (3× on a 90k-node grid); the Blender import gathers loops and finds loose edges without Python loops (3.7× on 300k polygons). Outputs are byte-identical.
- **`benchmark/bench.py --memory`** (roadmap 5.1.3, [every format](doc/benchmarks.md#every-format)): the peak resident memory each write and read adds, measured in a fresh process per operation; and a `stl_binary` row, which the sweep's default ASCII STL write never reached.
- **Flat tables in the facet and weld paths** (roadmap 5.4.2, 5.4.4, 5.5.1, 5.6, 5.7.3, [benchmarks](doc/benchmarks.md#flat-tables-in-the-facet-and-weld-paths)): `smooth`'s guard measures each cell once per pass (`smooth_volume` 1.5× faster at tier L); `region_adjacency` and `find_interface` group flat facet records (2.4× and 2.7×); the STL, glTF and WKT readers weld vertices by sorted fixed-size keys (ASCII `read_stl` 1.7×); `feature_edges` builds the skin alone; back-to-back ragged rows enter the core as one copy. Output is byte-identical, except that the glTF reader's `weld=True` now always merges `-0.0` with `+0.0`, as its Python twin does, and the WKT reader refuses a point of more than four coordinates.
- **`select_points(method="farthest")` in the core** (roadmap 5.10.2): the same selection, 2.4× faster on one thread for 1,000 of 1,000,000 points.
- **Benchmark rows** (roadmap 5.1.2): `find_intersections`, `tet_to_poly`, `poly_to_tet`, `thickness`, `extrude`, `crop`, `neighbors`, `read_stl_binary`, `read_gltf_weld` and `read_wkt` in `meshioplusplus_bench_ops`.
- **Frozen bucket grids, `orient_rings` without a map, `to_chars` for plain precisions** (roadmap 5.4.1, 5.7.1, [benchmarks](doc/benchmarks.md#spatial-grids-orientation-and-number-formatting)): the interpolation family, `periodic`, `check_conformity`, `find_intersections` and the point k-NN search a frozen `BucketTable` (`interpolate_cells` 1.6× on one thread, 2.2× on four); the per-cell face orientation every face table runs allocates nothing per cell (`feature_edges` 1.5×); `CNumber::Append` formats `%.<P>e`/`%.<P>g` with `std::to_chars` (3 to 3.6× a value) and the OBJ writer uses it. Output is byte-identical; under a comma locale the OBJ writer now repairs every coordinate of a line, not just the first.
- **The distance query searches a bounding-volume hierarchy; `find_interface` matches through a grid** (roadmap 5.3, 5.4.2, [benchmarks](doc/benchmarks.md#a-bounding-volume-hierarchy-for-the-distance-query-and-a-grid-for-find_interface)): the nearest-triangle search behind `sample_distance`, `distance_to_surface`, `compute_sdf`, `remesh_volume`, `hausdorff`, `shrinkwrap`, `voxelize`, `octree_mesh`, `tetrahedralize`'s octree backend, `register_rigid` and `fit_cad` walks a tree of the triangles' boxes instead of a bucket grid's shells, with the same answers bit for bit: 11.8× faster for `sample_distance` on one thread at tier L, and the 10-million-cell rows that timed out now finish. An occupancy pyramid over the grid was measured and not taken ([non-goals](doc/roadmap.md#non-goals-and-decisions-taken)). `grid_cell_size`, which sized the grid, is accepted and ignored in every binding. `find_interface`'s proximity mode looks up candidate facets in a bucket grid instead of projecting onto every facet of the other side (91× at tier L); the conforming mode groups flat records instead of a map per side. Benchmark rows `distance_to_surface_graded`, `find_interface_proximity`, `closest_points` and `closest_points_graded`.
- **A THREADS parallel backend, which the Linux wheels build** (roadmap 5.2, [installation](doc/installation.md)): `-DMESHIOPLUSPLUS_PARALLEL_BACKEND=THREADS` runs `parallel_for` on a pool of `std::thread` workers inside the core, which needs no runtime library, so the manylinux wheels, whose libgomp cannot be linked statically, run every parallel path (the zlib and gzip codecs, the distance query, the weld, the facet tables, the ASCII readers below) instead of none. The pool is sized by `MESHIOPLUSPLUS_NUM_THREADS`, else `OMP_NUM_THREADS`; a nested loop, or one started while another thread's loop holds the pool, runs on its calling thread; a forked child builds its own pool. Results are byte-identical to SEQ and OpenMP at every thread count. A CI leg builds and tests it.
- **Facet keys flattened to the width they need** (roadmap 5.4.3, [benchmarks](doc/benchmarks.md#facet-keys-without-records)): `extract_surface`, `extract_skin`, `smooth`'s boundary marking, `adjacency(kind="cell")`, the global face table and `find_interface`/`region_adjacency` group facets by keys of two to four 32-bit ids with no record per facet: `extract_surface` 2.6× faster on one thread at tier L, and the peak of the 10-million-cell row 6.5 GB → 4.7 GB.
- **`optimize_volume` profiled** (roadmap 5.5.2, [benchmarks](doc/benchmarks.md#profiling-optimize_volume)): 73% of its time is the worst-cell smoothing and 31% `acos` within it; a dihedral angle that cannot be a tet's least is no longer passed through `acos`, with the same result bit for bit: 1.37× faster at tier S.
- **Writers format one number at a time** (roadmap 5.7.1): the ASCII Gmsh, OFF and STL writers format their rows in parallel chunks through `to_chars`; the bytes are the same.
- **VTK XML parsed in place** (roadmap 5.7.4, [memory-mapped reading](doc/mmap.md#coverage)): the VTU/VTP/VTS/VTR/VTI readers parse the file's own bytes through a copy-on-write mapping instead of a whole copy of it.
- **Chunked parallel number parsing** (roadmap 5.7.2, [benchmarks](doc/benchmarks.md#chunked-number-parsing-and-writers-one-number-at-a-time)): the ASCII arrays of legacy VTK, VTU/VTP, Gmsh 2.2 `$Nodes` and Gmsh 4.1's node blocks are parsed in parallel chunks on a threaded build, with the same values and the same errors.
- **Fixed: numbers written under a comma-decimal locale** (roadmap 5.7.1): `snprintf_c` repaired only the first decimal separator of its text, so a format of several numbers (`cli`'s reports among them) kept commas after the first, and a literal `,` beside a number (FEBio's comma-separated values) became `.`; it now formats under the C numeric locale. The FLAC3D, MFM, SVG and TikZ writers formatted with the process locale outright and wrote `1,5`. `test_comma_locale_writers` writes every registered format under both locales and requires the same bytes, and CI installs a comma locale so these tests run.
- **ABI:** `MESHIOPLUSPLUS_ABI_VERSION` 39 -> 40 (Tier A): `detail::DistanceQuery` holds a `detail::SurfaceBvh` in place of its `BucketTable` and `mCellSize` (272 -> 152 bytes), and `detail/surface_distance.hpp` no longer includes `detail/bucket_table.hpp` and `detail/spatial_hash.hpp` ([ABI](doc/abi.md)). Additions in the same release (Tier B/C, [ABI](doc/abi.md)): `parallel.hpp`'s THREADS declarations and branch, and `detail/fast_number.hpp`'s `vsnprintf_classic` with the new body of `snprintf_c`.
- **SonarCloud on `master`** ([static analysis](doc/static_analysis.md)): the `coverage` job also runs a SonarCloud scan on pushes to `master`, with the merged compilation database of its two instrumented builds and the same coverage files Codecov receives (the C++ lcov tracefile rewritten in Sonar's generic format by `tools/lcov_to_sonar.py`); the step is skipped with a warning until the `SONAR_TOKEN` secret is set. The README shows its quality-gate and duplicated-lines badges.
- **Shared geometry and FEM kernels** ([design](doc/geometry_kernels.md), roadmap 3.4): the tet volume, the unit-edge corner determinant of the scaled Jacobian, the hexahedron and wedge corner tables and the per-cell centroid gather each live once (`src/cpp/src/detail/fem_kernels.hpp`, `cell_centroids.hpp`), and 70 file-local vector helpers in 27 sources give way to `detail/geometry.hpp`'s. Each replacement keeps the replaced arithmetic, so outputs are bit-identical; the copies whose arithmetic differs, and the shape functions, quadrature and topology tables still repeated, are roadmap 3.4's items. Roadmap 3.5 widens Clang-Tidy beyond include hygiene.
- **A second duplication pass** ([static analysis](doc/static_analysis.md#local-duplication-report), roadmap 3.4): `tools/dup_report.py` measures duplicated lines the way SonarCloud's detector does, on any checkout, and drove the pass: shared private helpers for the decimate pair, the topology operations' data copying, the data-transfer operations, the Jacobi solver, B-spline bases, segmentation, the VTK XML writers and several format helpers; one CLI argument block for 62 verbs; shared VTK legacy readers and pvtu/pvtp shims; and the repeated bodies of the Python binding and the C API. Duplicated lines fell from 10.6% to 9.3% of the C++ and from 11.0% to 9.9% of the Python. Outputs, Python signatures and docstrings, CLI help, C status codes and error texts are unchanged.

## v19.0.0 (2026-11-04)

A major release: `mesh_cad_surface` accepts the model's own tolerances and meshes sliver faces with their neighbours by default, and `octree_mesh` recovers more feature chains (nodes advance together, hand their place to a free neighbour, and the notches between chain nodes are filled). **ABI 39 (Tier A and B):** rebuild native consumers.

- **Breaking: `model_tolerances` and `virtual_faces` are on by default** ([mesh generation from CAD](doc/mesh_cad.md), roadmap 7.9.1). On the CAD corpus the two lose no face and together mesh 55 more of its 16,503, with 1,025 fewer open edges; they stayed off until a major version because the C API's released `mio_mesh_cad_surface_opts_ex` read zero as off. Every surface takes the new defaults: Python (`model_tolerances=True`, `virtual_faces=True`), the C++ `MeshCadSurfaceExtras` and so its two- and four-argument overloads, the pipeline's `ModelTolerances`/`VirtualFaces`, MCP, WASM, Julia, R, Octave / MATLAB and Fortran. The C struct keeps its layout and zero still means off: `mio_mesh_cad_surface_opts_ex_init` now sets both fields to 1, a NULL `opts_ex` takes them, and a struct zeroed by hand keeps them off. Both CLIs take `--no-model-tolerances` and `--no-virtual-faces`; `--model-tolerances` and `--virtual-faces` are still accepted and change nothing. Pass `model_tolerances=False, virtual_faces=False` for version 18's mesh.
- **Better feature chains in `octree_mesh`'s tetrahedral output** ([octree_mesh](doc/octree_mesh.md#the-tetrahedral-output), the exception to "output is unchanged" below). The nodes of a chain use a 0.1° dihedral floor and advance together in quarter steps, a node held back by a free boundary neighbour hands its place to it, and the notches left between consecutive chain nodes are closed with tetrahedra. New report fields `num_gaps_filled` and `num_gaps_skipped` in Python, the CLI, C, Fortran, Julia, R, Octave/MATLAB and WASM (`numGapsFilled`, `numGapsSkipped`). `OctreeMeshResult` gains two members (see the ABI note below); `mio_octree_mesh_report` takes them from its reserved tail and stays 392 bytes.
- **Parked: hexahedra of creased scans** ([octree_mesh](doc/octree_mesh.md#measured-and-parked), formerly roadmap 7.9.2). The cells `octree_mesh`'s hexahedral output keeps with a non-positive corner on scans (the Happy Buddha and the XYZ RGB dragon, a cell of the bunny) are now a documented limit of the output, which the warnings already report, after two routes were measured and left out: fitting to a skin smoothed first (the Buddha with features off: 168 cells to between 101 and 149), and letting the boundary nodes off the skin while untangling (the Buddha 261 to 219 uniform and 115 to 113 graded, the dragon 219 to 221, at four to five times the time). The cells left are held by the grid's connectivity, not by the fit. Nothing in the output changes. With it, roadmap §7 (new capabilities) is closed and scan metrology and reverse engineering is §7, its items 8.1 to 8.9 now 7.1 to 7.9.
- **ABI:** `MESHIOPLUSPLUS_ABI_VERSION` 38 -> 39 (Tier A and B): the default member initializers of `MeshCadSurfaceExtras` changed (Tier B, no layout moved), and `OctreeMeshResult` gained `mNumGapsFilled` and `mNumGapsSkipped` after `mNumFlips` (Tier A, shifting `mGuaranteeApplies` and the members after it). See [the ABI history](doc/abi.md).

## v18.3.0 (2026-11-04)

A feature release: an Octave / MATLAB binding and `decimate_volume` in the remaining language bindings. No C++ ABI change (ABI stays 38). Note: v18.2.0 was never tagged; this tag carries its changes too.

- **Added: `decimate_volume` in Fortran, Julia, R and Octave / MATLAB** ([decimate_volume](doc/decimate_volume.md#other-language-surfaces)): the tetrahedral counterpart of `decimate`, through `mio_decimate_volume_ex`, with the `frozen` pin list and 1-based maps (`0` for absent): the point map everywhere, and the per-block cell maps in Julia, R and Octave (Fortran returns no cell maps for any operation). It was the one native operation Python exposed that these bindings lacked. Fortran also gains the cell-type queries R and Octave already had (`mio_cell_type_dimension`, `mio_cell_type_num_nodes`).
- **Added: an Octave / MATLAB binding** ([Octave / MATLAB](doc/octave.md)): `bindings/octave/meshioplusplus` binds the installed C library for GNU Octave and MATLAB with every function of the R binding, as `mio.<name>` (`mio_read` -> `mio.read`). It is plain C over the MEX API (one gateway, `meshioplusplus_mex`) plus MATLAB-compatible `.m` wrappers, built by Octave's `pkg install` or by `mio_build` (`mkoctfile --mex` / MATLAB `mex`). Arrays put one entity per row (`num_points x dim`, `num_cells x nodes_per_cell`), indices are 1-based, data arrays keep their stored class, and meshes, format side channels, sequences and XDMF/Exodus series are `handle` objects whose ids a generation-checked registry validates, so a released, stale or forged handle raises instead of crashing. The new CI job `octave` runs the suite after both builds; `tests/python/test_octave_binding_parity.py` keeps the binding in step with R (every export and `.Call` entry point, with matching argument counts) and rejects Octave-only syntax. Development and CI use GNU Octave 8; MATLAB is supported through the shared MEX API but not exercised in CI.

## v18.2.0 (2026-11-04)

A feature release: level-set cutting (`cut_level_set`, `cut_quadrature`, through the new optional dependency CutCells), healing of CAD at read time, external tetrahedral meshers (TetGen, Gmsh), `remesh_quads`, TetGen `.smesh`, materials and a better hexahedral fit in `octree_mesh`, and a cgnslib link fix. **ABI 38 (Tier A):** rebuild native consumers.

- **Spike: surface booleans** ([findings](doc/spikes.md#surface-booleans-formerly-roadmap-7-8), formerly roadmap 7.8): a private prototype in the core (`detail/mesh_boolean`, with Shewchuk's expansion arithmetic moved out of the predicates into `detail/expansion.hpp`, the predicates unchanged) computes the union, intersection and difference of two closed triangle surfaces through an exact arrangement of edge-plane points, per-triangle exact retriangulation and exact ray-parity classification. On a seeded synthetic corpus every transversal case succeeds with the volume identities met to 1e-14, but rounding the output to doubles leaves most curved and rotated results self-intersecting, and coplanar contact is not handled, so no public `mesh_boolean` is queued. `meshioplusplus_boolean_spike` (built with the C++ tests) and `tools/boolean_corpus.py` measure it; the weekly `boolean_corpus` workflow runs it on Thingi10K pairs. No API or ABI change.
- **Added: healing CAD at read time** ([STEP reading](doc/formats/step.md#reading), roadmap 7.7.1): `step.read(..., heal=True)` and `iges.read(..., heal=True)` run `ShapeFix_Shape`, then `BRepBuilderAPI_Sewing` at `sew_tolerance` (at most 0: 1e-5 of the bounding-box diagonal, raised to the shape's own largest tolerance but never past 1e-3 of it; a positive tolerance sews without `heal`), before the B-rep is extracted. What it did is the `heal` member of the B-rep's file-level JSON (`healed`, `fixed`, `sew_tolerance`, `free_edges_before`, `free_edges_after`, `multiple_edges`, `degenerated`): two faces whose shared edge is written twice, 1e-4 mm apart, read with eight open edges and, healed, with the outer six. C++ `CadReadOptions::mHeal`/`mSewTolerance`; C `mio_read_with_info2` with `mio_cad_read_opts`; Fortran's, Julia's and R's `read_with_info`; WASM's `readMeshSelective(..., {cadRead})`; `--heal`/`--sew-tolerance` on both CLIs' `convert` and `mesh-cad-surface`; `heal`/`sew_tolerance` on the MCP `convert` and `mesh_cad_surface` tools.
- **Added: external tetrahedral meshers** ([tetrahedralize](doc/tetrahedralize.md#external-meshers-tetgen-and-gmsh), roadmap 7.7.2): tetrahedral meshers are registered by name besides the default (`add_tet_mesher`, `tet_mesher(name)`, `tet_mesher_names()`), and `tetrahedralize(backend=<name>)` runs one. Every native build registers `tetgen` and `gmsh` when those programs are installed (on `PATH`, or `MESHIOPLUSPLUS_TETGEN`/`MESHIOPLUSPLUS_GMSH`), and runs them as separate processes, never linked: TetGen through a `.smesh` with `-pYQ` (inner shells as holes), Gmsh through an STL and a `.geo` with `-3`. `tetrahedralize_backends()` lists the names; `auto` is unchanged. The core now checks every mesher's boundary itself (points back bit-equal, the tetrahedra's one-sided faces the surface's triangles) instead of trusting its flag, and refuses one that moved it by name. On every surface: C `MIO_TETRAHEDRALIZE_BACKEND_NAMED` with `provider`, the report's `backend_name`, `mio_tet_mesher_count`/`_name`; Fortran, Julia, R; both CLIs' `--backend NAME` (`--version` lists them); the pipeline's `Backend`; MCP's `backends_available`. Never in WebAssembly.
- **Added: `remesh_quads`** ([field-aligned quads](doc/remesh_quads.md), roadmap 7.7.3): a triangle surface remeshed into quads along a smooth cross field by an installed QuadriFlow (MIT) or Instant Meshes (BSD-3), run as a separate process through a new provider kind, `QuadRemesherProvider`, registered by name (`add_quad_remesher`, `quad_remesher_names()`; `remesh_quads_backends()`). On the unit sphere at `h = 0.1` QuadriFlow makes 2,602 quads, no triangles, with a least scaled Jacobian of 0.368 (0.25 to 0.58 across seeds, the mean 0.987), where recombining `mesh_cad_surface`'s own triangles leaves 0.116 at the poles; the report gives the quads, the scaled Jacobian and the distance to the input. On every surface: C `mio_remesh_quads` with `mio_remesh_quads_opts`/`_report` and `mio_quad_remesher_count`/`_name`, Fortran, Julia, R, WASM (`remeshQuads`, which always throws there), both CLIs (`remesh-quads`), the pipeline (`RemeshQuads`) and MCP. CI builds QuadriFlow from a pinned commit; Instant Meshes is supported but untested.
- **Added: TetGen `.smesh`** ([TetGen](doc/formats/tetgen.md#the-smesh-surface)): the surface file TetGen meshes reads and writes in both engines: nodes, then `triangle`, `quad` and `polygon` facets with `tetgen:ref` markers.
- **Fixed: a cgnslib built against a system HDF5 failed to link** (roadmap 7.1.4). CGNS's exported CMake targets name their HDF5 dependency `hdf5-shared`/`hdf5-static` without declaring it when HDF5 came from FindHDF5 (Ubuntu's), so `-DMESHIOPLUSPLUS_WITH_CGNSLIB=ON` asked the linker for `-lhdf5-shared`; the configure now stands those names in for the HDF5 it found. A new CI job, `cgnslib`, builds CGNS 4.5.2 from its pinned tag and runs the CGNS suites with the backend live, `CgnsMll.LengthUnitsAgreeWithCgnslib` included, which no leg had run.
- **Added: `cut_level_set` and `cut_quadrature`** ([level-set cutting](doc/cut.md)): the part of a mesh that one or several level sets select (scalar `point_data` arrays or planes, combined by CutCells' expressions such as `"a < 0 and b > 0"` or `"phi = 0"` for the interface), cut from cells of every family (line, triangle, quad, tetra, hexahedron, wedge, pyramid) into straight pieces of their own family (`backend="lut"`) or curved Lagrange pieces (`"quadrays"`), the uncut cells inside kept, point data interpolated in each piece's parent and cell data and cell regions carried (`cut:parent_cell`, `cut:cut`); and quadrature rules of any order on that part (cut-cell quadrature for unfitted finite elements), as a point cloud with `quadrature:weight`, `quadrature:reference`, `quadrature:rule` and `quadrature:parent_cell`. A level set is quadratic on `triangle6`/`tetra10` meshes. Both run [CutCells](https://github.com/sclaus2/CutCells) (S. Claus, MIT), a new optional dependency (`MESHIOPLUSPLUS_WITH_CUTCELLS`, found by `find_package(CutCells)`; `build/build-cutcells.sh` builds the pinned commit), which the Linux, macOS and Windows wheels and the full WebAssembly artifact link (MSVC lacks `__int128`, so `build/build-cutcells.sh` patches the pinned sources there); without it both refuse naming the option. On every surface: Python, C++ (`operations/cut.hpp`, additive), C (`mio_cut_level_set`, `mio_cut_quadrature`, `mio_cut_opts`, `mio_cut_report`, `mio_has_cutcells`), Fortran, Julia, R, WASM (`cutLevelSet`, `cutQuadrature`, `hasCutcells`; the lean artifact refuses by name), both CLIs (`cut`, `cut-quadrature`), the pipeline (`CutLevelSet`, both engines) and MCP. A new CI job builds the pin and runs the suites.
- **ABI:** `MESHIOPLUSPLUS_ABI_VERSION` 37 -> 38 (Tier A): `CadReadOptions` appends `mHeal` and `mSewTolerance` (16 -> 32 bytes) and `TetrahedralizeOptions` appends `mProvider` (80 -> 112 bytes); `TetrahedralizeBackend::Named`, the named tet-mesher and quad-remesher registrations in `providers.hpp` and the new header `operations/remesh_quads.hpp` ride along as pure additions. See [the ABI history](doc/abi.md).
- **Added: materials in `octree_mesh`'s hexahedral output** ([octree_mesh](doc/octree_mesh.md#the-hexahedral-output), roadmap 7.9.3). `output="hex"` with `conformity="cleaving"` gives one material per nested shell, as the tetrahedral output does (`octree_mesh:material`, `material_<k>`). The materials are made manifold one layer inside the next, each interface is pillowed on both sides and fitted to its own shell, and `hausdorff_to_skin` measures the interfaces too. Measured: two nested spheres keep a smallest corner of 0.60 (uniform) and 0.47 (graded), three keep 0.48 and 0.28, each material within 3% of its shell's volume, conforming. No option or ABI change: the option existed, and a one-shell skin gives the same bytes as before.
- **Changed: `octree_mesh`'s hexahedral fit leaves out creases shorter than a cell** (roadmap 7.9.4, narrowed to 7.9.2). On a scan most creases are noise; they are no longer snapped, and the warnings and `num_feature_chains_missed` count them. Hexahedra with a non-positive corner, uniform / graded: Stanford bunny 5 / 0 → 2 / 0; decimated Happy Buddha 684 / 486 → 283 / 102; XYZ RGB dragon 1 516 / 1 237 → 254 / 66. A new warning counts those lying where the skin is thinner than two cells. Skins whose chains are longer than a cell (the cube, the capped cylinder) give the same bytes, as do all four `octree_mesh_hex` rows of `bench_ops --hash`; the Stanford bunny's hexahedra change.
- **Fixed: graded hexahedra of nested shells.** The graded dual dropped the centres within a tenth of a cell of any skin, which opened a cavity at an inner shell; it then pillowed and folded (two nested spheres: −0.99 in 18.0.0). Only the boundary's centres are dropped now, decided by winding-number probes, and a centre on a skin lying on the lattice's planes takes the middle of its two sides' winding numbers. Single-shell skins give the same bytes.

It pins the base wheel's exact version, ships OpenCASCADE 7.6.3 as shared libraries beside its own extension (`MIT AND LGPL-2.1-only WITH OCCT-exception-1.0`), and registers its kernel when `meshioplusplus` first needs one. Without it, reading STEP or IGES raises `NotImplementedError` naming the add-on, and `fit_cad` uses its native backend. `MESHIOPLUSPLUS_NO_PLUGINS=1` skips the discovery, and an add-on of another version is refused by name. Source builds, the native CLI, Conan, vcpkg and both WebAssembly artifacts are unchanged: they compile OpenCASCADE into the core as before.
- **Added: a runtime provider registry** ([`providers.hpp`](doc/python_packages_plan.md#the-provider-registry-core)): `CadKernelProvider`, `TetMesherProvider` and `RemesherProvider`, each with `register_*`, `unregister_*` and an accessor (`cad_kernel`, `tet_mesher`, `remesher`), and `register_builtin_providers`. `tetrahedralize` asks the mesher per closed region and `adapt`, `discretize_levelset`, `mesh_domain` and `move` ask the remesher; the Netgen and MMG code moved to `src/cpp/providers/{netgen,mmg}`. `read_step`, `read_iges`, `fit_cad` and the capability queries (`cad_read_has_occt`, `fit_cad_has_occt`, `fit_cad_occt_version`) ask it instead of a compile-time switch. The OpenCASCADE code moved to `src/cpp/providers/occt/` and reaches the native `fit_cad` helpers through `detail/fit_cad_native.hpp`.
- **Added: the shared core in the base wheel.** `MESHIOPLUSPLUS_PYTHON_SHARED_CORE=ON` links `_core` against `libmeshioplusplus_core_meshio` installed in `meshioplusplus/lib` with the headers and the CMake package, and `meshioplusplus.get_cmake_dir()` returns the package directory. The Linux wheels keep a static libstdc++ with its symbols exported, which lets exceptions cross between the core and an add-on. `MESHIOPLUSPLUS_ADDON=occt` builds only the add-on's extension against an installed base wheel, and `build/build-occt.sh PREFIX --shared` builds the shared OpenCASCADE it links.
- **Added: the add-on wheels `meshioplusplus-netgen` and `meshioplusplus-mmg`** ([installation](doc/installation.md#what-the-pypi-wheels-contain)): `pip install "meshioplusplus[netgen]"` gives `tetrahedralize` its Netgen backend, `"[mmg]"` gives `adapt`, `discretize_levelset` and `mesh_domain` (the wheel is built without ELAS, so `move` raises naming it). `has_netgen()` is public beside `has_mmg()` and `has_occt()`, the MCP `tetrahedralize` tool reports `netgen_available`, and `build/build-netgen.sh` builds Netgen 6.2.2401 shared.
- **Added: the permissive libraries in the base wheel on Linux and macOS** (roadmap 4.7): HDF5, netCDF, cgnslib, zstd, LZ4, bzip2 and KaHIP are linked static with hidden symbols (`build/build-permissive-libs.sh`, `MESHIOPLUSPLUS_PREFER_STATIC_DEPS`), so the HDF5, netCDF and CGNS formats and the codecs run natively in the wheel and h5py or netCDF4 can sit beside them in one process. The Windows wheels keep the Python fallbacks.
- **Added: provider plugins for the native CLI and the C API** ([C++ API](doc/cpp_api.md#providers-and-plugins), not on Windows): `MESHIOPLUSPLUS_PLUGIN_PATH`, `load_plugin`, `load_plugins`, `mio_load_plugins` (with Fortran, Julia and R wrappers) and `-DMESHIOPLUSPLUS_BUILD_PLUGINS=ON`, which builds the OpenCASCADE, Netgen and MMG providers as shared libraries. `meshioplusplus --version` lists the backends a run has.
- **Changed: `wheels.yml`** builds the base wheel without OpenCASCADE and a `build_occt_addon` job per runner from that wheel, tests the pair with `tests/wheel_occt_smoke.py` and publishes `meshioplusplus-occt` as its own PyPI project after the base wheel. The Windows core DLL takes its export table from `cmake/gen_core_def.py` (auto-export overflows the 65,535-export limit). The repair steps for the pair, and the PyPI trusted publisher for the new project, are first exercised by the release run.
- **ABI:** pure addition (`providers.hpp`, plus the plugin functions declared there), `MESHIOPLUSPLUS_ABI_VERSION` stays 36; see [ABI reviews](doc/abi_reviews.md).

- **Added: `find_intersections`** (roadmap 3.1.2, [intersections](doc/find_intersections.md)): where a surface intersects itself, or where two surfaces interpenetrate or touch. Candidate triangle pairs come from a bucket grid over their boxes and each is decided by the exact `orient3d`/`orient2d` triangle–triangle test the boundary layer already used, so every hit is exact and there is no "possible" class; on one surface, triangles sharing corners (bitwise-equal coordinates, so unwelded seams are not crossings) count only when they meet beyond them. Returns the input with `intersections:count` per cell, the sorted cell pairs and the crossing segments as a line mesh (`intersections:cell_a`/`cell_b`); coplanar overlaps are counted and flagged without a segment. On every surface: Python, C (`mio_find_intersections` and its opaque result), Fortran, Julia, R, WASM, both CLIs (`find-intersections`, exit 1 on a hit), MCP and a `FindIntersections` pipeline gate.
- **Added: `thickness`** (roadmap 3.1.4, [thickness](doc/thickness.md)): wall thickness and clearance per facet, by a ray from each cell's centroid along its normal through a bounding-volume hierarchy of the target surface: inward it stops at the far side of the wall, outward at the next wall facing it, on the same surface or on a second part. Returns the input with `thickness:distance` (NaN for a miss) and `thickness:hit_cell`, and the least, largest and mean distance with where the least was measured; `threshold` counts the thin facets. The ray–triangle kernel is factored out of `tri_bvh_ray` once (`detail::ray_triangle`, with a filtered cast beside it) and its existing callers are unchanged. On every surface: Python, C (`mio_thickness`), Fortran, Julia, R, WASM, both CLIs (`thickness`, `--min` exits 1 below it), MCP and a `Thickness` pipeline step.
- **Added: Netgen in the full WebAssembly artifact** ([lean and full builds](doc/wasm.md#lean-and-full-builds), [tetrahedralize](doc/tetrahedralize.md)): `meshioplusplus_wasm_full[_mt]` links Netgen 6.2.2401's nglib statically, built from the pinned tag by `build/build-wasm-deps.sh --full` with one build patch, so `tetrahedralize` in the browser keeps the surface's triangles and points (`hasNetgen()` is true there). The lean artifact stays Netgen-free; its `backend: 'netgen'` now names the full artifact instead of a CMake flag. The full pair's licence expression gains Netgen's LGPL-2.1 (`MIT AND (LGPL-2.1-only WITH OCCT-exception-1.0) AND LGPL-2.1-only`). KaHIP's tarball also falls back to a commit-verified clone of its tag, as netCDF's and CGNS's do.
