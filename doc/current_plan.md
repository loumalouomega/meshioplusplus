# Close roadmap §1 "WASM parity"

## Context

`doc/roadmap.md` §1 lists what the WASM build (`@meshioplusplus/wasm`) lacks relative to the other surfaces, measured against its main downstream consumer (the Kratos MDPA Preview VS Code extension). The branch `wasm-parity` is at master (`648d6e3b`, v11.1.0, ABI 12); nothing of §1 has landed. The user confirmed the scope is **everything in §1**, after which the section is removed (roadmap rule: "a closed item is removed, not struck through") and the sections renumbered.

§1 has three tiers, and they are staged as separate releases so each ships against its probe:

| Tier | Items | Core change | Release |
| --- | --- | --- | --- |
| A | Loader error, integer dtypes, parity guard, index maps, side channels, write options, written paths, `frozen` on every flat binding, `decimateVolume`, stateful sequence reader | none in `src/cpp` (C header additive) | v11.2.0 |
| B1 | In-file timelines: MED, CGNS, Tecplot, Gmsh, EnSight | readers + metadata | v11.3.0 |
| B2 | OpenFOAM zones, multi-region, decomposed cases, time-directory fields | reader/writer | v11.4.0 |
| B3 | Gmsh 4.1 physical tags for untagged regions | writer | v11.5.0 |
| B4 | VTK XML `.vts`/`.vtr`/`.vtm` | new formats | v11.6.0 |
| close | Remove §1, renumber §2–§9 → §1–§8, regenerate diagram, version-only major bump | — | v12.0.0 |

Precedent: v10.38–10.40 closed the previous §1 bullet by bullet with a minor bump each, then `5e600dd1` was a version-only major bump (15 mechanical files) marking the closure.

Ground rules that apply to every tier (from `AGENTS.md`):

- Every `src/cpp` change: regenerate `src/single_include/meshioplusplus/meshioplusplus.hpp` (`tools/amalgamate.sh`), keep `tests/cpp/test_abi_layout.cpp` current, and add a row to `doc/abi_reviews.md` naming each changed installed header. `tools/check-abi-version.sh` diffs against the last **tag**, which is `v11.0.0` (v11.1.0 was never tagged), so the first row of this work must also name `detail/cell_faces.hpp`, `formats/gid.hpp`, `operations/agglomerate.hpp`, `version.hpp`. Layout or inline-body changes to an existing struct bump `MESHIOPLUSPLUS_ABI_VERSION`; pure additions do not.
- Every release: the ten version files, `find_package` pins in `README.md`/`doc/cpp_api.md`, the four `BASELINE_HASHES` in `tests/python/test_io_baseline.py` (reverse-substitute first), a dated `CHANGELOG.md` entry, `npm install` in `src/viewer/` for the lock file.

- WASM verification: `source ~/src/emsdk/emsdk_env.sh && ./build/configure-wasm.sh --build && node tests/wasm/smoke.mjs` (both variants; `--seq-only` leaves `_mt` stale). Native: `build/configure.sh --tests --build` with `-DMESHIOPLUSPLUS_WITH_NETCDF=OFF` locally, `ctest` serially. Python: `.venv/bin/python -m pytest tests/python/<file>`.
- Roadmap: each tier's commit removes or narrows its §1 items (`AGENTS.md` checklist).

- **`.vtm` (MultiBlock).** Write: `<vtkMultiBlockDataSet><Block index=0><DataSet index=i name=... file="<stem>/<stem>_<i>.vtu"/>`; one piece file per **cell block** of the mesh (each piece a single-block mesh with that block's cell data and the full point data; points are shared, so each piece carries the full point array — document, or prune unused points via `clean(remove_orphans)` per piece: prune, so pieces are self-contained; keep it deterministic). Written paths: the index plus every piece, which tier A's written-paths mechanism reports automatically. `registry_extension_defaults` gains `.vts`, `.vtr`, `.vtm`. `registry_metadata_readers` gains all three (vts/vtr: extents only; vtm: sum of the pieces' metadata).
