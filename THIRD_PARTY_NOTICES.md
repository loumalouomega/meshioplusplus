# Third-party components in the meshio++ binaries

meshio++ itself is MIT ([LICENSE](LICENSE)). The binaries the project publishes — the PyPI wheels (the `meshioplusplus._core` extension), the release command-line executables, the Blender extension and the Conan and vcpkg packages built with OpenCASCADE — link the libraries below statically, except libomp on macOS, which the macOS wheels are expected to bundle as a shared library (to be confirmed). [What the wheels contain](doc/installation.md#what-the-pypi-wheels-contain) lists what they leave out. A build from source links whichever of the optional native libraries it finds (see [installation](doc/installation.md)); the WebAssembly package lists its own in [`src/wasm/THIRD_PARTY_NOTICES.md`](src/wasm/THIRD_PARTY_NOTICES.md).

| [zlib](https://zlib.net/) | 1.3.1 | Zlib | yes | yes |
| [gidpost](https://www.gidsimulation.com/) (vendored) | 2.14 | BSD-2-Clause-Views | yes | yes |
| [pugixml](https://pugixml.org/) (vendored) | 1.14 | MIT | yes | yes |

**OpenCASCADE is LGPL-2.1 with the OCCT exception**, so the published binaries are not plain MIT: their licence is `MIT AND (LGPL-2.1-only WITH OCCT-exception-1.0)`, as [`LICENSE-BINARIES.md`](LICENSE-BINARIES.md) states in every artifact. The meshio++ sources, and a build from source that does not link OpenCASCADE (`-DMESHIOPLUSPLUS_WITH_OCCT=OFF`, or no OpenCASCADE found), are MIT.

## Robust geometric predicates

The exact `orient2d`, `incircle`, `orient3d` and `insphere` tests of `mesh_cad_surface`'s triangulator (`src/cpp/src/detail/predicates.cpp`) implement the method of J. R. Shewchuk, *Adaptive Precision Floating-Point Arithmetic and Fast Robust Geometric Predicates* (Discrete & Computational Geometry 18, 1997), whose reference code Shewchuk placed in the public domain. They are written from the paper, are MIT like the rest of meshio++, and add no component to the table above; the attribution is recorded here and in `CITATION.cff`. No code from Triangle, TetGen, Gmsh, CGAL or the CDT library is used.

## Hexahedral transition schemes (CinoLib)

`octree_mesh`'s graded hexahedra (`hex_grading="graded"`) port code from [CinoLib](https://github.com/mlivesu/cinolib) (MIT, Copyright (C) 2016 Marco Livesu; authors Luca Pitzalis, Marco Livesu and Gianmarco Cherchi): the eight transition schemes for strongly balanced grids of `include/cinolib/hex_transition_schemes.h`, as integer tables generated by `tools/gen_hex_dual_schemes.py` into `src/cpp/src/detail/hex_dual_scheme_tables.cpp`, and the scheme detection, marking and orientation of `hex_transition_install.cpp` and `hex_transition_orient.cpp` and the dual of `dual_mesh.cpp`, rewritten in `src/cpp/src/detail/hex_dual_schemes.cpp`. Both files carry CinoLib's MIT notice. The method is Livesu, Pitzalis and Cherchi, *Optimal Dual Schemes for Adaptive Grid Based Hexmeshing* (ACM Transactions on Graphics 41(2), 2022), with the pairing of Pitzalis, Livesu, Cherchi, Gobbetti and Scateni, *Generalized Adaptive Refinement for Grid-based Hexahedral Meshing* (ACM Transactions on Graphics 40(6), 2021). MIT like meshio++, it adds no component to the table above.

## OpenCASCADE and the LGPL

OpenCASCADE's licence is the GNU Lesser General Public License 2.1 (`LICENSE_LGPL_21.txt`) with the additional exception in `OCCT_LGPL_EXCEPTION.txt`, which permits using its headers' inline code and templates without the resulting object code becoming a "work based on the library". Both texts ship beside this notice in every wheel (its `.dist-info/licenses`), every CLI archive and the Blender extension, which carries the wheel.

The binaries link OpenCASCADE statically, as the CAD kernel of `fit_cad` and of STEP and IGES reading. To let a recipient exercise the LGPL's right to relink against a modified OpenCASCADE, every binary is reproducible from source:

1. The OpenCASCADE source is the upstream tag `V7_6_3`, commit `b079fb9877ef64d4a8158a60fa157f59b096debb`, unmodified (no patches are applied).
2. `build/build-occt.sh PREFIX` fetches that commit, verifies it, and builds the static libraries (`build/occt-recipe.sh` holds the pin and the configuration). Configuring meshio++ with `OpenCASCADE_ROOT=PREFIX` (or `-DOpenCASCADE_DIR=PREFIX/lib/cmake/opencascade`) links them: `pip install .` for the wheel, `build/configure.sh --cli --build` for the executable. The workflows that build the published binaries, `.github/workflows/wheels.yml` and `.github/workflows/cli.yml`, run exactly these steps. All of it is in the meshio++ repository at the tag of the binary's version.
3. Replacing the OpenCASCADE checkout with a modified one (or pointing `OpenCASCADE_ROOT` at any compatible OpenCASCADE 7.6 or later, static or shared) and rebuilding produces a binary linked against it.

## Netgen

[`tetrahedralize`](doc/tetrahedralize.md)'s backend is [Netgen](https://github.com/NGSolve/netgen)'s nglib (J. Schöberl; LGPL-2.1-only). It is never vendored and never in the published binaries: a build from source links it only when configured with `-DMESHIOPLUSPLUS_WITH_NETGEN=ON` (`build/configure.sh --with-netgen`), and then only dynamically, against the shared `libnglib` and `libngcore` of a Netgen install (`NETGEN_ROOT`, or the distribution's `libnglib-dev`), so a recipient can replace them without rebuilding meshio++. A binary built that way carries Netgen's licence beside meshio++'s MIT; without the option no Netgen code is built or linked, and `tetrahedralize` uses its native octree backend instead (asked for Netgen by name, it throws `Unsupported` naming the flag).

## Licence texts

OpenCASCADE's are named above. zlib's is in the header of its source distribution at the version above (the pin is in `CMakeLists.txt`, `MESHIOPLUSPLUS_ZLIB_STATIC`); the vendored gidpost's is `src/cpp/third_party/gidpost/LICENSE` in the meshio++ repository. pugixml's MIT notice is in the header of `src/cpp/third_party/pugixml/pugixml.hpp`, nlohmann/json's is in its own header, and libomp's is in its own distribution (to be confirmed for the macOS wheels).
