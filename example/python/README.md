# Examples (Python)

Jupyter notebooks demonstrating meshio++'s Python bindings on the bundled
[`../example.msh`](../example.msh) (a Gmsh 4.1 mesh of a mechanical bracket,
~52k nodes / ~298k elements).

| Notebook | What it shows |
|----------|---------------|
| [`01_read_and_visualize.ipynb`](01_read_and_visualize.ipynb) | Read the Gmsh file with meshio++, inspect the mesh, and render it with PyVista (full view + a clipped interior view). |
| [`02_convert_and_inspect.ipynb`](02_convert_and_inspect.ipynb) | Convert the geometry to VTU / VTK / XDMF / Gmsh / PLY, compare file sizes, and verify the round trip. |
| [`03_mesh_operations.ipynb`](03_mesh_operations.ipynb) | Tour of the operations layer -- surface/skin extraction, quality, reorder, diff, transform, clean, crop (bounding box / half-space / data predicate), merge, split, stats, convert_cells, refine, partition, smooth, interpolate, regular grids and signed distance fields (`grid`, `voxelize`, `compute_sdf` voxel/octree, `.vti`), slice, isosurface, gradient, the settings pipeline, sequences, the five data operations, and selective reads -- each rendered with PyVista. |
| [`04_interop.ipynb`](04_interop.ipynb) | Hand the mesh to PyVista, trimesh and Arrow/Parquet with no file round-trip -- shared buffers checked with `np.shares_memory`, `zero_copy_only`, regions through a PyVista round-trip, and a Parquet export read back with pandas. Needs `meshioplusplus[interop]`. |
| [`05_point_clouds.ipynb`](05_point_clouds.ipynb) | Read PCL's own `.pcd` files (ASCII, binary, `binary_compressed`, organised), render the colour-coded cloud, write every `DATA` mode and compare sizes, then `subsample_points` → `proximity_graph`, and the column rules and chemistry-XYZ refusal of `.xyz`. |
| [`06_lsdyna_decks.ipynb`](06_lsdyna_decks.ipynb) | Read a multi-file LS-DYNA keyword deck (long-format nodes, I10 solids, free-format shells, `*INCLUDE_PATH`), render it one colour per `*PART`, see the tetra/pyramid/wedge collapse with a positive-volume check, the four card formats reading to one mesh, `*SET_*` as point/cell/side regions, and a write → read round trip. |
| [`07_calculix_frd.ipynb`](07_calculix_frd.ipynb) | Read CalculiX `.frd` results written by `ccx`: the increments as sequence steps, the deformed cantilever coloured by von Mises (with a beam-theory check), the first four bending modes of the same beam, `read_sequence` → `{step}` files, shells and beams that `ccx` expands into solids, the he20/pe15/be3 node permutations checked geometrically, the short layout and the cgx shell types, derived fields against NumPy, and the `tensor_invariants` data operation (mises/principal/hydrostatic/deviatoric) reproducing `derived=True`'s output exactly. |
| [`08_gltf_export.ipynb`](08_gltf_export.ipynb) | Write a mesh as glTF 2.0 and look at what a viewer sees: an L-bracket with two cell regions and a boundary patch, the skin's point normals smooth versus split at a crease angle (`compute_normals`), a temperature field baked into an unlit `COLOR_0`, the `.glb` decoded by hand (root node rotation, scale, recentring; linear colours displayed as sRGB), the source coordinates recovered exactly, and a point cloud exported as `POINTS` with normals. |
| [`09_format_half_gaps.ipynb`](09_format_half_gaps.ipynb) | Roadmap §1.1's other four items, each a small self-contained mesh: SU2 multizone (`NZONE=`, unwelded zones, `su2:zone`), Tecplot multiple zones (mixed cell types sharing points via `VARSHARELIST`, one region per zone), EnSight Gold variable write (scalar/tensor `point_data` and `field_data`, binary, round-tripped), and OpenFOAM binary write (`label_bits`/`scalar_bits`, bit-exact against the ASCII write, file-size comparison). |
| [`10_unv_universal_files.ipynb`](10_unv_universal_files.ipynb) | I-DEAS universal files (`.unv`/`.uff`) from gmsh and pyuff: quadratic tetrahedra and wedges with their groups as regions, three mode shapes of a 2414 file read as steps and warped, a measured FRF set (dataset 58 and binary 58b) read as a frequency sequence and plotted, and a write-back of groups and one result step. |
| [`11_nastran_h5.ipynb`](11_nastran_h5.ipynb) | MSC Nastran HDF5 results (`.h5`) written by MSC Nastran 2020: the model with its element and property ids and one region per property, static displacements and per-cell shell stress, the steps of six solution sequences, four buckling modes of a SOL 105 file warped, the real and imaginary parts of a frequency response, a thermal transient, a bit-for-bit check against pyNastran, and one `.vtu` per mode. |
| [`12_code_aster.ipynb`](12_code_aster.ipynb) | Code_Aster native meshes (`.mail`): a HEXA20 block with a face group and a node group sharing one name, one element of each of the twenty keywords from `POI1` to `HEXA27`, Code_Aster's node order against MED's and meshio++'s with a mid-edge check, a `.mail` → `.med` → `.mail` round trip, and what the writer emits (80 columns, sanitised group names). |
| [`13_optistruct_comsol.ipynb`](13_optistruct_comsol.ipynb) | Altair OptiStruct decks and COMSOL meshes: HyperMesh components (by `$HMMOVE` and by property) and OptiStruct `SET`s as regions, a real OptiStruct deck from pyNastran, regions written back as components by both engines; COMSOL domains, boundary entities and Selections, COMSOL's quadratic node order with a mid-edge check, `.mphtxt` against `.mphbin`, and an OptiStruct deck converted to COMSOL. |
| [`14_elmer_febio.ipynb`](14_elmer_febio.ipynb) | Elmer mesh directories read with no format (the directory is sniffed), bodies and boundaries as regions, a quadratic beam written for ElmerSolver with its `820` node order and regenerated boundary parents, ElmerGrid partitions merged back; an FEBio `.feb` with every solid type, sets, surfaces and MeshData, written back as spec 4.0; FEBio `.xplt` results, compressed and not, rendered state by state and converted to a `.vtu` sequence. |
| [`15_ansys.ipynb`](15_ansys.ipynb) | Ansys MAPDL: a `.cdb` deck's degenerate SOLID186 wedge, pyramid and tetrahedron read from their repeated nodes, components as regions, missing midside nodes created, a deck written with MAPDL's own layouts and read back; `.rst` results, a modal analysis rendered mode by mode and converted to a `.vtu` sequence, and an `.rth` temperature field. |
| [`16_patran_femap_mfem.ipynb`](16_patran_femap_mfem.ipynb) | Interchange files: a Patran neutral file's packets and components as regions, its quadratic cells read from Patran's own node order; a Femap model's property titles and groups, its degenerate-brick node slots, and EMSolution's output sets read as steps in both result encodings; MFEM's curved order-2 meshes in MFEM's degree-of-freedom numbering, with grid functions, written back with their `.gf` files. |
| [`17_libmesh_z88_fil_radioss.ipynb`](17_libmesh_z88_fil_radioss.ipynb) | FEM formats of v16.7.0: a libMesh mesh read the same from `.xda` and `.xdr`, a refined mesh reduced to its active cells with its boundary carried down; a Z88 cantilever with Z88R's displacements and stresses, found by its file name and written back; an Abaqus `.fil` file's increments as steps in ASCII and both binary byte orders, real Abaqus output checked against pybaqus; an OpenRadioss starter deck's cards, parts, groups and surfaces. |
| [`18_marc_ansys_results.ipynb`](18_marc_ansys_results.ipynb) | v16.8.0: an MSC Marc deck read from fixed, extended and free-format cards with its element and node sets, a `.dat` told apart from Tecplot's; a Marc `.t19` post file's increments as steps with its stress tensor at the integration points; Ansys `.rst` element stresses and strains per element node and averaged, nodal forces in equilibrium with the reactions, a distributed solve merged to MAPDL's combined file, and a cyclic sector expanded to the full rotor. |
| [`19_d3plot_op2_results.ipynb`](19_d3plot_op2_results.ipynb) | v16.9.0: an LS-DYNA d3plot family read state by state, its deleted elements removed through the `lsdyna:alive` mask and its plastic strain per integration point or layer; real LS-DYNA output and its global energies over a sequence; a Nastran OP2 SOL 101 model with its property regions and stresses, three mode shapes as steps, and an OP2 whose mesh comes from the input deck beside it. |

## Running them

The notebooks are committed **with their outputs** so they render on GitHub
without any setup. To re-run, install the notebook/rendering extras and execute
head-lessly:

```sh
uv pip install --python ../../.venv pyvista matplotlib jupyter nbconvert ipykernel
PYVISTA_OFF_SCREEN=true \
  ../../.venv/bin/jupyter nbconvert --to notebook --execute --inplace *.ipynb
```

PyVista renders off-screen through VTK's EGL backend (VTK ≥ 9.5), so no display
or `xvfb` is required; if GL is unavailable the notebook falls back to a
matplotlib surface plot.
